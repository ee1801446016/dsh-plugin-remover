# dsh-plugin-remover

**在 DeepSeek Harness 里删除一个对话——连同它留下的东西——并且删错了能拿回来。**

侧栏会话行的「⋯」菜单里，紧挨着「归档会话」多了一行「删除对话…」。点开后你可以逐项决定带走什么；删除默认进入回收站，可以整组恢复或只恢复某一个文件。

## 它解决什么问题

DSH 的会话持久化层明确没有删除接口：

- `@deepseek-ai/dsh-session-persistence`：*"No deletion or retention API — pruning stored sessions is out-of-band backend maintenance."*
- `@deepseek-ai/dsh-session-persistence-jsonl`：*"Nothing deletes session files."*
- `@deepseek-ai/dsh-attachment-local`：附件对象永不自动清理，也没有回收机制。

而且有两类对话**在界面上完全够不着**：

- **子代理（subagent）对话**被 harness 从侧栏过滤掉了（`sessionVisible()` 对 `origin === 'subagent'` 直接返回 false），没有行 → 没有行菜单 → 任何挂在行菜单上的删除项对它们都无效；
- 父对话删掉之后，子代理对话连「对话头部切换器」这个唯一入口也没了，id 变成磁盘上一串没人认识的目录名。

本插件因此提供两层入口，并把「删除」做成可撤销的。

## 界面

### 1. 会话行菜单

侧栏任意会话行，鼠标移上去 → 行尾 **⋯** → **「归档会话」的下一行**就是 **「删除对话…」**。

### 2. 侧边栏右下角

侧边栏底部、**「设置」行上方**有一个回收站按钮：展开时是「图标 + 回收站」一行，收成 56 px 图标栏时是一个方形图标。点它直接打开回收站面板。

这个入口在**每一个页面都在**，不需要会话行，也不需要先打开插件页。它可以在插件详情页里关掉（见下）。

### 3. 插件详情页

**插件 → 对话移除与回收站**（该页同时是安装/停用入口）。页面里有一块属于本插件的区块：

| 行 | 内容 | 「打开」后 |
|---|---|---|
| 回收站 | N 组 · 体积 | 回收站面板 |
| 隐藏的子代理对话 | N 个 | 隐藏对话面板 |
| 回收站设置 | 保留天数 · 容量上限 | 回收站面板（设置区） |

区块底部还有一个勾选框 **「在侧边栏显示回收站入口」**，默认**勾上**。取消勾选后侧边栏那个按钮立刻消失（不用刷新），回收站仍然可以从这一页打开——关掉的只是侧栏快捷方式。

这块区块**不依赖任何会话行**，所以上面那两类「够不着的对话」全部从这里进入。会话行菜单和侧栏按钮都只是顺手的快捷方式。

### 4. 三个对话框

- **删除对话框**：扫描结果 + 勾选 + 「移入回收站」。
- **回收站面板**：分组列表、展开明细、恢复、永久删除、三项设置。
- **隐藏对话面板**：列出全部子代理对话，逐个删除（走同一个删除对话框）。

三个对话框都做了**尺寸与滚动**的处理：宽度按视口自适应（删除对话框上限 760 px，回收站与隐藏对话 600 px），高度封顶在视口内，内容区自己带滚轮、标题栏吸顶。所以即使把「详细信息」全部展开，底部的「移入回收站」也始终留在视口里，不会被推出屏幕。

## 删除对话框里有什么

对话框**逐区列出**，每一区单独勾选：

| 区 | 默认 | 说明 |
|---|---|---|
| **对话文件** | 必选 | 该对话的存储目录（`<DSH_HOME>/sessions/<项目>/<会话id>/`），以及投影缓存 |
| **子代理对话** | 全选 | 该对话派生出的全部子代理对话（含孙代）。父对话一没，它们就没有入口了，所以默认一起删 |
| **产出的文件** | 全选 | 该对话用 `write` / `edit` / `str_replace_editor` 写过的文件 |
| **引用的文件** | **全不选** | 该对话用 `read` / `read_image` 读过、但没有写过的文件 |
| **附件对象** | 选中 | 你拖进输入框的图片/文件；只删没有被其他对话引用的 |

「产出的文件」和「引用的文件」**逐条可勾**，不勾的一个字节都不动。两区都有「全选 / 全不选」和一个按路径筛选的搜索框。

### 「详细信息」按钮

**每一份可选文件后面都有一个「详细信息」按钮**，点开在行内展开：

```
来源目录   D:\work space\TEST\_purge-patch\lib
完整路径   D:\work space\TEST\_purge-patch\lib\index.js
大小       41.6 KB
来源对话   「把刚才的删除功能整合进插件」(父对话) · 写入方式 write / edit ×3
           「review-pass-2」(子代理) · 写入方式 write ×1
```

- **来源目录**是重点：一堆同名文件里，靠目录才认得出是哪一个。
- 同一文件被多个对话写过/读过时，**逐条列出**来源对话。
- 「引用的文件」把「写入方式」显示为「读取方式」。
- 面板是**行内展开**（不是嵌套弹窗），因为弹层套弹层会打乱焦点陷阱；窄屏自动换行。

回收站面板展开某组时，每一行明细也带「详细信息」，显示它的原路径与所在目录。

## 确认与危险操作

删除是分级的，确认也分级：

| 操作 | 可恢复 | 确认方式 | 按钮 |
|---|---|---|---|
| 删除对话（含子代理、产出文件、引用文件、附件） | 是，在回收站里 | **不需要勾选** | 「移入回收站」，正常主色 |
| 恢复某一组 / 某一个文件 | — | 不需要 | 「恢复」 |
| 清空回收站 | **否** | **勾选「我已知晓：永久删除后无法恢复」** | 「永久删除」，危险色 |
| 永久删除某一组 / 某一个文件 | **否** | **同上** | 「永久删除」，危险色 |
| 本次删除放不进回收站 | **否** | **同上** | 「永久删除」，危险色 |
| 回收站过期自动清理 | **否** | 无需确认（设置里约定的） | — |

勾选之后按钮**直接执行**，不再二次确认。

## 回收站

### 存放位置

固定为 `<DSH_HOME>/dsh-plugin-remover/trash/`。`DSH_HOME` 未设置时是用户目录下的 `.dsh`（Windows 上通常是 `%USERPROFILE%\.dsh`）。

一次删除 = 一个组：

```
trash/
  settings.json                          # 保留天数、容量上限、侧栏入口开关
  groups/<时间戳>-<会话id>/
    manifest.json                        # 这一组的清单，恢复就靠它
    store/<项目>/<会话id>/                # 对话文件（整目录一项）
    artifacts/<n>/<原文件名>              # 产出文件
    referenced/<n>/<原文件名>             # 引用文件
    attachments/<n>/<sha256>             # 附件对象
    cache/<会话id>.json                   # 投影缓存
```

组目录先建成 `<组名>.partial`，全部搬完再原子改名，所以中途崩溃不会留下一个「看起来能恢复、其实不完整」的组。

### 跨盘处理

回收站在 `C:`，而你的工作区常常在别的盘。`rename` 不能跨卷，所以这种情况会走 **复制 → 校验字节数一致 → 删源**。校验不一致就**保留源文件**并报错——不做半删。

### 恢复

- **整组恢复**：组行上的「恢复」。
- **单文件恢复**：展开组，明细行上的「恢复」。
- 恢复到**原路径**；原位置已有文件时**不覆盖**，该条报「目标已存在」并保留在回收站里。

### 三项设置

| 设置 | 默认 | 含义 |
|---|---|---|
| 保留天数 | **30** | 超过就自动清除；`0` = 永不自动清除 |
| 容量上限 | **2 GB** | 超过时删除会**先问你**；`0` = 不限 |
| 侧边栏入口 | **开** | 是否在侧边栏右下角显示回收站按钮 |

前两项改完立刻对已有分组生效（「到期时间」是按当前保留天数现算的，不落盘）。越界值会被钳制（天数 0–3650，上限 0–1 TiB）。第三项是一个勾选框，勾/取消立刻生效，侧栏马上跟着变。

三项都只写**你改动的那一个字段**：写保留天数不会把容量上限或侧栏开关重置回默认。

到期的清理只在有请求时顺带做（打开面板、删除前），不会常驻定时器。

### 容量超了会怎样

**绝不静默删除旧的回收站内容来腾地方**——那正是回收站要防的事。取而代之是一次询问：

- 本次要移入多大、上限多少、当前已用多少；
- 选「**永久删除本次内容**」→ 直接删，不进回收站；
- 或选「**先清空回收站，再重试**」→ 清空现有内容后本次照常进回收站；
- 如果**连清空也放不下**，只留「永久删除」并说明原因。

这个询问会**勾选 + 危险按钮**，勾了才动。询价发生在**任何文件移动之前**，所以「放不下」不会留下半删状态。

## 安全边界（全部在宿主端强制，前端说了不算）

- **会话 id、回收组 id、组内路径**都按「单个安全路径段 / 安全相对路径」校验后才参与路径拼接；`..`、绝对路径、反斜杠一律拒绝。
- **产出/引用文件**只有在真实路径**严格位于**某个被删对话记录的 `cwd` 之内、且**不在 `DSH_HOME` 内**时才可动。不在其中的、不是普通文件、realpath 无法解析（例如符号链接指向外部）的，一律跳过并在对话框里说明原因。
- **浏览器只提交「会话 id + 勾选的 id + 布尔开关」**，路径一律不传；宿主端会从会话日志**重新推导整个计划**，因此前端内存里的数据无法扩大删除范围。宿主自己没产出过的 id 解析为空。
- **附件对象**只有在读遍所有其他已存储会话、确认无人引用后才删；任一读取失败按「仍被引用」处理。被同时删除的父/子对话不参与「其他会话」的判断，避免它们互相保护自己的附件。
- **`/plugins` 路由不受登录态保护**，所以所有接口都要求本插件自己的标记头 `x-dsh-plugin-remover: 1`，并在带 `Origin` 时校验同源。别的网页发起的跨站请求设不了这个头（会先触发预检），因此无法借你的浏览器删东西。
- **永久删除必须有 `confirm: true`**，宿主端强制校验，漏传直接拒绝。
- 运行中的对话先停：子代理走 `subagents.interrupt`（它没有 Workspace 行可归档），普通对话走 `archiveSession({stopActivity:true})`；停完再动文件。

## 安装 / 更新 / 卸载

这是一个标准 DSH bundle，`cordis.patch.yml` 已随包提供：

```yaml
- insert:
    - id: remover
      name: dsh-plugin-remover
```

包内已带预构建的 `lib/`，**没有 `prepare` / `postinstall` 脚本**，所以三种装法都不需要批准构建授权：

```sh
# 从 npm（推荐）
dsh plugin --profile <profile> add dsh-plugin-remover

# 从 GitHub 源码
dsh plugin --profile <profile> add github:OWNER/dsh-plugin-remover

# 从本地目录（链接安装，改文件即刻生效）
dsh plugin --profile <profile> add ./dsh-plugin-remover
```

也可以在**插件 → 添加插件**里选本地目录。

- **更新**：把本 bundle 在插件管理器里**关一次再开**（宿主半立即重载，不必重启整个 DSH）；浏览器半（`lib/client.js`）由 HMR 推送到已打开的页面，必要时刷新。从 npm 安装的版本还可用插件管理器的「更新」按钮。
- **卸载**：插件页面停用或移除。回收站目录**不会**被自动删除——那是你的数据，需要的话自己清 `<DSH_HOME>/dsh-plugin-remover/trash/`。

## 已知限制

- **只识别写作类 / 读取类工具调用的目标路径**：`write`、`edit`、`str_replace_editor`、`create_file` 与 `read`、`read_image`。`pwsh` / `bash` 里重定向或脚本生成的文件**扫不出来**。
- **运行中对话的日志仍可能被写入**：已经先停再动，但 Windows 上若句柄未释放，移动会失败并把原因写进结果；源文件保留，稍后重试即可。
- **共享附件**：内容寻址存储会去重，同一对象可能被多个对话引用。「彻底带走附件」因此有时会保留部分，这是有意的。
- **列表刷新**：`api-session/removed` 是尽力而为的广播；可靠做法是重新加载页面，删除成功后对话框就是这么做的。
- **大目录跨盘移动较慢**：附件量级可达数百 MB，UI 会显示「正在移入回收站…」。
- **在 DSH `0.2.2-rc.3` 上验证**（desktop profile）。`engines.dsh` 因此声明为 `>=0.2.2-rc.1 <0.3.0-0`；换到别的版本请先跑离线验证，并核对 `sidebar.workspaces.session.menu.item`、`sidebar.footer.action`、`plugins.detail.section`、`shell.overlay` 四个槽位契约是否仍然一致。
- **依赖宿主的客户端组件**：`lib/client.js` 从 `@deepseek-ai/dsh-client-ui-primitives` 取了 `Button`、`Checkbox`、`Modal`、`MenuItemButton` 与几个图标。这些包会随宿主无预警变更，某次升级若删改了其中一个成员，插槽会直接渲染失败（控制台报 `slot entry crashed`）。`verify-client.cjs` 里有一条「no unverified primitive is imported」守卫，但升级宿主后仍建议先跑一遍验证。

## 代码结构与验证

| 位置 | 作用 |
|---|---|
| `lib/index.js` | 宿主半：计划推导、选择集、回收站、隐藏对话 |
| `lib/client.js` | 浏览器半：删除对话框（含逐文件详细信息）、回收站面板、隐藏对话面板、插件页区块 |
| `locale/` | 插件名与描述的本地化文案（`meta.title` / `meta.description`） |
| `icon.svg` | 插件页图标 |
| `verify/` | 四套验证（宿主离线 / 客户端离线 / 实机已服务 bundle / 端到端） |

运行验证：

```sh
node verify/verify-host.mjs     # 宿主半，离线，不需要 DSH 在跑
node verify/verify-client.cjs   # 浏览器半，离线
node verify/verify-served.mjs   # 实机；读 DSH_WEB_URL，没有就 SKIP
```

端到端（真正删除一个对话、再从回收站恢复）：

```sh
node verify/seed-e2e.mjs                                  # 造一个合成对话，打印它的会话 id
node verify/verify-e2e.mjs <上面打印的 id>                 # 删除→回收站→恢复→再删除→永久清掉
```

`seed-e2e.mjs` 会在 `<DSH_HOME>/sessions/` 与 `<DSH_HOME>/storages/session_projcache/` 里写一个真实格式的合成会话，并在 `%USERPROFILE%\dsh-plugin-remover-e2e\` 下建一个临时工作区。它不碰你的任何对话；跑完 `verify-e2e.mjs` 会把它彻底删掉。
